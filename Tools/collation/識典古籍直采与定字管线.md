# 識典古籍（shidianguji.com）文本直采管线

用于《明實錄》等古籍的底本直证与定字。本目录下的脚本在 `.errata_tmp/`（工作副本，未入库），
参照语料与台账已归档于此目录。

## 1. 站点结构

識典古籍是 Next.js（edenx）服务端渲染站点，页面内嵌 `window._ROUTER_DATA` JSON，
**无需浏览器**即可取全文：

| 用途 | URL 形式 |
|---|---|
| 卷页（整卷正文） | `https://www.shidianguji.com/zh/book/{bookId}/chapter/{chapterId}` |
| 对页（左右两半叶） | `https://www.shidianguji.com/zh/mid-page/{midPageId}` |
| 检索 | `https://www.shidianguji.com/zh/search/{urlencoded查询}` |

`明實錄` 的 bookId = `LS0026`（北京大學-字節跳動古籍開放文本庫，明抄本）。
目录（3118 章）在一次 book 页请求的 `loaderData['__session/(lang$)/book/$'].bookInfo.catalog.chapters`
中即可全量取得，含 `chapterId` / `chapterName` / `startPageNum` / `parentChapterId`。

注意：`/zh/chapter/{id}` 与 `/zh/bible/...` 均无 SSR 数据，必须带 `book/{bookId}` 前缀。

## 2. 文本抽取

`sd_chap.py`（单卷）与 `xz_dl.py`（批量）：

1. `curl` 取 HTML（普通 UA 即可，不需要 cookie/JS）；
2. 花括号配平法截取 `window._ROUTER_DATA` 后的 JSON；
3. `loaderData` 中带 `paragraphList` 的节点即正文，逐 `content`（JSON 字符串）取
   `lines[].content`；
4. 逐行写出 `xxx.txt`。

已归档：`Tools/collation/tmp/ming_shilu_ref/001.txt … 224.txt`（《大明孝宗敬皇帝實錄》全 224 卷，
约 3.3 MB），`cids.json` 为卷次→chapterId 映射。

## 3. 定字流程（探针定位 + 左右夹逼）

对目标文本中每个 `□` 串：

1. **正规化**：目标转繁体并归一异体（`align10.VAR` 表：衛/衞、于/於、並/并、巡/廵、升/陞、
   敕/勑、鹽/塩、佥/僉、場/塲、狹/陜、沈/瀋、勋/勛、規/䂓、啇/啇 …）；`□` 串替换为哨兵字符。
2. **探针定位**（`probe2.py`）：取 `□` 左、右各若干字的干净片段为探针，在对照卷中检索全部命中，
   按「左右两探针间隔≈□串长度」「探针越长越好」「命中唯一者优先」综合罚分排序，取前若干候选。
3. **链式对齐**（`align21.py`）：按干净片段唯一命中的锚点单调放置，段间桥接行走，空缺并入 `□` 串。
4. **左右夹逼验证**（`strict.py: flank_score`）：把候选字代入目标后，检查候选字左右两侧是否与对照卷
   连续吻合，返回 `(left, right)` 游程。

### 判据

| 类别 | 条件 | 处置 |
|---|---|---|
| `LEFT+RIGHT` | 左≥8 且右≥8 字连续吻合 | 直接采用（高置信） |
| `LEFT`/`RIGHT` | 单侧≥12 字连续吻合 | 采用（中置信，需看语境） |
| `NONE` | 两侧均不足 | 挂账 |

实测：单侧长夹逼（如 L12110「旌其门曰**雙**节」左 227 字）与双侧夹逼结论一致，
且能有效排除跨卷误配（批一曾出现 `端`/`積` 等因误配窗口而假阳性的候选，夹逼法一律判 NONE）。

## 4. 反例与注意

- **探针重复**：目标与对照本用字系统不同（如「讟」「說」），短探针可能命中他处，务必用夹逼复核。
- **底本自有讹脱**：如 L11345「改葬□□□」对照本作「改葬咅」——三缺一，只能补一字，余缺保留。
- **拆字残留**：`氵□兀虫□` 类为底本把一个字拆成「形旁＋□＋声旁」，夹逼法会给出「形旁+声旁」的
  参考读法，需人工判断是补一字还是保留原残。
- **同名异卷**：同一人名地名在不同卷重复出现，探针必须取得足够长（≥12 字）才具区分力。
